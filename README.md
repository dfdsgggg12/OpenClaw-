零基础 OpenClaw 养虾实战：避开无效配置，打造可自主干活的 AI 智能体
OpenClaw 装好只是开始。很多人一上来就接一堆工具、写一大段提示词，结果 Agent 要么不动，要么乱动。养虾先养水，养 Agent 先养配置。所谓“养虾”，就是持续调教一个能自主干活的智能体。下面这条实战路径，帮你避开无效配置。

一、先跑通最小闭环。 别追求全能。选一个具体任务，比如“每天整理行业新闻并生成摘要”。只给一个模型、一个搜索工具、一个输出目标。能稳定完成，再加工具。最小闭环跑不通，加再多功能都是空中楼阁。

二、提示词要具体。 无效配置最常见的是目标模糊。“帮我处理业务”等于没说。要写清楚：你是谁、服务谁、目标是什么、可用工具、禁止事项、输出格式、什么时候停止。越具体，Agent 越不容易跑偏。

三、工具不是越多越好。 每个工具都要有清晰名称、说明和参数。只保留当前任务必需的。工具多了，模型会乱选，调用链变长，错误率飙升。工具之间要有依赖顺序和异常分支：超时怎么办、没权限怎么办、数据为空怎么办。没有异常处理的 Agent，一遇意外就卡死或编造。

四、记忆和知识库要分层。 短期记忆记住当前对话和任务进度，长期知识库存制度、文档、历史案例。不要把所有资料一股脑塞进去，检索要精准。否则 Agent 会拿着过期信息当真理。知识库要定期更新，标注有效期。

五、权限必须最小化。 这是企业级养虾的红线。Agent 只能访问完成当前任务所需的数据和操作。敏感动作如发邮件、改数据、下单、转账，必须加二次确认或人工审批。所有操作留审计日志。还要防提示注入，用户可能诱导它越权。没有护栏的自主，等于灾难。

六、先建议后自动。 新 Agent 不要直接放开手。先让它只给建议，人确认后执行。跑一段时间，统计任务完成率、人工接管率、错误类型。稳定后再逐步放权。设置熔断机制：连续失败、超时、异常调用达到阈值，自动暂停并转人工。

七、日志是水质检测。 记录每次思考、工具调用、返回结果和耗时。每周分析 bad case，看是提示词问题、工具问题还是知识库问题。不要只看成功案例。失败案例才是改进方向。

八、选对场景。 高频、规则清晰、交付明确的任务最适合。比如客服工单分类、销售线索初筛、日报生成、监控告警汇总。不要一上来做万能助手。小场景跑通，再横向复制。

九、持续迭代。 业务会变，工具会变，知识会过期。Agent 不是一次性项目，而是需要日常运营的“虾”。定期补数据、调提示词、换工具、清权限。建立反馈入口，让用户一键标记“答错了”。

OpenClaw 养虾的核心不是堆配置，而是克制。少工具、清目标、严权限、勤观察。避开无效配置，才能让智能体从玩具变成真正能自主干活的数字员工。先跑通一个小闭环，再慢慢养大。你的 Agent 不需要一开始就完美，但必须每一步都可控、可查、可回滚。这样养出来的虾，才活得久、干得稳。
